# Вопросы GameMind: стандарт качества

Существующие вопросы **не трогаем** без прямой просьбы владельца.
Новые — только как **DRAFT** через пайплайн (`docs/CONTENT_PIPELINE.md`).
Переводы — `docs/QUESTION_I18N.md`, картинки — `docs/QUIZ_IMAGES.md`.

## Хороший вопрос

1. **Один бесспорный правильный ответ.** Факт проверяется по первичному
   источнику (официальный сайт, кредиты игры, вики издателя, MobyGames,
   Wikipedia с источниками). Спорное, «по слухам», «по мнению фанатов» — нет.
2. **Не устаревает.** Без «последняя часть серии», «на сегодня», «текущий
   рекорд». Если нужно время — точный год.
3. **Проверяет знание или опыт, а не умение гуглить.** Лучше механика,
   момент сюжета, деталь мира, «как это работает», чем голая дата.
4. **Без подсказки в формулировке** (слово из ответа в вопросе, грамматика,
   которая подходит только к одному варианту, самый длинный вариант = верный).
5. **Правдоподобные неверные варианты** из того же «класса» (студия —
   студиями, персонаж — персонажами той же вселенной/жанра). Не шуточные.
6. **Коротко:** вопрос до ~140 символов, вариант до ~40 (жёсткие лимиты:
   вопрос 10–500, вариант ≤ 200).
7. Без спойлеров к свежим (≤ 2 лет) играм на EASY/MEDIUM.

## Сложность

| Уровень | Кто ответит | Пример темы |
|---|---|---|
| EASY | Любой, кто слышал об игре | главный герой, студия хита, жанр |
| MEDIUM | Кто играл | механика, локация, предмет, второстепенный герой |
| HARD | Фанат серии / жанра | деталь мира, редкая механика, история разработки |

После публикации сложность подтверждается статистикой (доля верных ответов);
расхождение → пересмотр в админке.

## RU / EN

- **Варианты — одни и те же ответы на двух языках**, а не разные наборы.
  Плохо: RU «Куб Эдгара» / EN «Edgeless Safety Cube» в одной позиции.
- Названия игр/студий — как официально в регионе; если официального RU нет —
  латиницей во **всех** вариантах (стратегия B из `QUESTION_I18N.md`),
  не смешивать кириллицу у верного и латиницу у неверных.
- EN звучит естественно для носителя, а не как машинный перевод RU.

## Формат партии

Файл: `content/drafts/batches/YYYY-MM-DD-<тема>-<кол-во>.json`, контракт v1
(`docs/CONTENT_PIPELINE.md` §4): ровно 4 варианта, ровно один `isCorrect`,
`metadata` с `game` / `franchise` / `topic` (+ `platform`, `year`, `genre`,
когда появится таксономия фазы 4.0), уникальный `draftKey`.

Пример метаданных:
```json
{ "game": "Portal 2", "franchise": "Portal", "topic": "mechanic", "year": 2011 }
```

## Процесс

1. Согласовать с владельцем тему и объём партии (обычно 20–40 вопросов).
2. Проверить дубли: поиск по ключевым словам в существующих вопросах
   (dev-БД, только чтение) и в прежних партиях `content/drafts/batches`.
3. Написать партию, к каждому факту — источник в `metadata.source` (URL).
4. `npm run content:validate-drafts -- <file> --fail-on-publish-blockers`
5. Импорт в **dev** как DRAFT: `npm run content:import-drafts -- <file> --dry-run`,
   затем без `--dry-run`.
6. Владелец смотрит в админке → «На ревью» → «Опубликовать».
7. Прод-импорт — только по команде владельца (`CONTENT_PIPELINE.md` §10).

## Новые типы вопросов

Каждый тип — это `QuestionType` в схеме + форма админки + форма снапшота +
подсчёт очков на сервере + UI-компонент + контракт черновика. Перед кодом —
ADR в `docs/DECISIONS.md`. Для `AUDIO_GUESS` — отдельно решение по авторским
правам (короткие фрагменты, источник, удаление по запросу).
